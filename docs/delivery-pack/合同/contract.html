本版本的乙方为自然人（个人）。相比单位主体，下列五处是实质差异，均已在正文中处理，签署前请重点确认：

  1. 税与发票（第四条）——个人通常无法自行开票，需向税务机关代开；甲方是个人所得税的法定扣缴义务人。第 4.2 条给出「含税价 / 税后价」两种方案，必须二选一勾定，否则实际到手金额会有 20%–40% 的争议。
  2. 非劳动关系声明（第七条）——不写清楚，长期、按月、受管理的开发合作有被认定为事实劳动关系的风险，甲方要补社保、经济补偿金，乙方的权利义务也变得不确定。
  3. 乙方无冲突保证（第 6.7 条）——个人承接开发的头号风险是与本职工作的劳动合同、保密协议、竞业限制或职务作品条款冲突。此条是甲方的必要保护，也是对乙方的提醒。
  4. 责任限额（第十六条）——个人的赔偿能力有限。本版将保密与数据条款的责任从「无限」改为「合同总价款的 N 倍」，比单位版更贴近现实，倍数是谈判点。
  5. 履约能力（第 18.4 条）——个人可能因病、意外或失联无法继续。此条约定通知义务、解除权与交付物移交，甲方不可省。

第一条　定义与解释

除上下文另有所指，本合同中下列用语含义如下：

1.1 本系统：指乙方依本合同为甲方开发的「肌松大师 · 门店预约与经营管理系统」，包含顾客端微信小程序、员工端页面、Web 管理后台及服务端，具体范围见附件一。

1.2 交付物：指本合同附件一列明的、乙方应向甲方交付的软件、源代码、数据库脚本、文档及其他成果。

1.3 定制开发成果：指乙方为履行本合同专门开发、且仅服务于本项目业务逻辑的部分，包括但不限于本系统的业务代码、数据库结构设计、接口设计与界面设计。

1.4 乙方既有成果：指乙方在本合同签订前已独立开发、或在本项目之外独立开发的、不以本项目为唯一用途的通用工具、框架、组件、脚手架及方法论。

1.5 第三方平台：指本系统运行所依赖的、由第三方提供且非双方所能控制的平台与服务，包括但不限于微信开放平台、微信小程序平台、微信支付、微信云托管及甲方选定的云服务商。

1.6 工作日：指中华人民共和国大陆地区法定工作日，不含法定节假日及休息日。

1.7 书面形式：包括纸质文件、电子邮件、经双方确认的项目管理系统记录及双方书面确认的即时通讯记录。

1.8 缺陷：指本系统的实际表现与附件一功能清单、附件三验收标准不符的情形。因甲方变更需求、甲方或第三方修改代码、第三方平台变更或甲方运行环境异常导致的不符，不属于本合同项下的缺陷。

第二条　项目范围与交付物

2.1　乙方应按附件一《交付物与功能清单》的约定，向甲方交付本系统及相关文档。附件一为本合同不可分割的组成部分，与正文具有同等效力。

2.2　交付物包括但不限于：

  1. 顾客端微信小程序完整源代码（含员工端页面）；
  2. Web 管理后台完整源代码；
  3. 服务端完整源代码及数据库结构迁移脚本；
  4. 自动化测试用例集；
  5. 部署运维文档、接口文档、系统设计文档；
  6. 一次生产环境部署与上线支持。

2.3　除附件一明确列明者外，下列事项不属于本合同范围，如甲方需要，双方另行签订补充协议并另行计价：

  1. 硬件设备、网络带宽、云服务器、数据库实例及其他基础设施的采购与费用；
  2. 本系统与甲方或第三方既有系统（如 ERP、财务系统、会员系统、硬件门禁等）的对接开发；
  3. 数据迁移，即将甲方历史业务数据导入本系统；
  4. 苹果 App Store、安卓应用市场等微信生态之外渠道的应用开发；
  5. 内容运营、美工设计（附件一已列明者除外）、推广投放；
  6. 质保期届满后的运行维护。

2.4 关于示例数据　乙方为演示与测试目的在系统中预置的门店、技师、项目、订单等数据为示例数据，不构成甲方的真实经营数据。上线前由甲方按附件六提供真实基础数据，乙方负责导入并清除示例数据。

第三条　项目周期与里程碑

3.1　项目总工期为 个自然日，自启动日起算。

第四条　合同价款、发票与税费

4.1　合同总价款为人民币 元（大写：）。

4.2 税费承担　双方就税费承担方式约定采用下列第 种（二选一，签署前须勾定；未勾定的，视为采用方式一）：

方式一　含税价

第 4.1 条所列价款为含税价，已包含因本合同产生的全部税费，含乙方应缴纳的个人所得税、增值税及附加。甲方依法履行个人所得税代扣代缴义务，自各期应付款中代扣后支付余额，并在扣缴后向乙方提供完税凭证。乙方已就该期款项自行完税并提供有效完税凭证的，甲方不再重复扣缴。

方式二　税后价

第 4.1 条所列价款为乙方实际到手金额。因本合同产生的个人所得税、增值税及附加由甲方另行承担并依法申报缴纳，不从应付乙方的款项中扣减。

4.3 发票　乙方应按下列约定向甲方提供合规票据：

  1. 乙方为自然人的，应向主管税务机关申请代开发票并交付甲方。代开过程中产生的税费依第 4.2 条约定的方式承担。
  2. 乙方已登记为个体工商户或个人独资企业的，由乙方自行开具 发票。
  3. 依法可不开具发票的，双方以《收款收据》及完税凭证作为入账依据。
  4. 乙方未按约定提供发票或完税凭证的，甲方有权暂缓支付相应款项，直至票据交付；该等暂缓不构成甲方逾期付款，不适用第 4.6 条的违约金。

4.4 支付计划　见附件二，基本结构如下：

期次支付条件比例
第一期（预付款）本合同生效后 5 个工作日内30%
第二期（里程碑款）附件二里程碑 M2 交付并经甲方确认后 5 个工作日内30%
第三期（验收款）系统通过终验（依第九条）后 10 个工作日内30%
第四期（质保金）质保期届满且无未决缺陷后 10 个工作日内10%

4.5　合同总价款已包含乙方为履行本合同所发生的全部人工、差旅及其他费用。第二条 2.3 款所列范围外事项、第三方平台与基础设施费用不在其内。

4.6　甲方逾期付款的，每逾期一日按逾期金额的 0.03% 向乙方支付违约金；逾期超过 30 日的，乙方有权暂停开发与服务，暂停期间不计入乙方工期，且乙方不承担由此产生的迟延责任。

4.7　甲方应将款项支付至本合同首部载明的乙方账户。该账户户名须与乙方姓名一致；乙方要求支付至他人账户的，甲方有权拒绝。

5.2　甲方应指定 1 名项目负责人，作为需求确认、变更审批与验收的唯一对接人，并授予其相应决策权限。项目负责人变更的，应提前 3 个工作日书面通知乙方。

5.3　甲方应按附件六的要求，及时、完整、真实地提供：

第八条　需求变更

8.1　任何一方提出变更需求的，均应填写附件五《需求变更单》，经双方签字确认后生效。

8.2　变更单应载明变更内容、对工期的影响天数、对价款的增减金额。未经双方书面确认的变更，乙方无义务实施；已实施的，不影响乙方按原范围主张验收与付款。

8.4　口头、临时性的沟通意见不构成需求变更。

第九条　交付与验收

9.1 交付方式　乙方以下列方式交付：源代码通过 Git 仓库移交并授予甲方管理员权限；文档以电子文件形式交付；生产环境由乙方完成一次部署并演示系统可正常运行。

9.2　验收标准见附件三。

9.3 验收流程

  1. 乙方完成开发后书面提交验收申请，并提供交付物清单与自测报告；
  2. 甲方应在收到申请后 15 个工作日内组织验收，并出具书面验收意见；
  3. 验收通过的，双方签署《项目验收确认书》，签署之日为终验日；
  4. 验收不通过的，甲方应在验收意见中逐项、具体地列明不符合附件一或附件三的事项。乙方应在 10 个工作日内修复并提请复验，复验流程同上。

9.4 视为验收通过　有下列情形之一的，视为验收通过，终验日为该情形发生之日：

  1. 甲方在收到验收申请后 15 个工作日内未组织验收，亦未书面说明正当理由；
  2. 甲方提出的验收意见未逐项列明不符合附件一或附件三的具体事项；
