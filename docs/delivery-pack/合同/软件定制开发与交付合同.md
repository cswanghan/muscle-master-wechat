# 附件三 验收标准与流程

## 一、功能验收

**1.1** 附件一列明的功能全部实现，且能按业务流程正常运行。

**1.2** 下列**主流程**必须端到端跑通：

| 序号 | 主流程 |
| --- | --- |
| 1 | 顾客登录 → 选门店 → 选项目 → 选技师与时段 → 下单 → 支付 → 生成核销码 |
| 2 | 前台核销 → 技师开始服务 → 完成服务 → 顾客评价 |
| 3 | 前台散客开单 → 现金或扫码收款 → 核销 |
| 4 | 服务中加钟 → 补收款 → 完成 |
| 5 | 改约、换技师，且原时段正确释放 |
| 6 | 退款：低于审批阈值直接退，高于阈值进入审批，审批通过后原路退回 |
| 7 | 储值充值 → 下单自动抵扣 → 余额不足部分走微信支付 → 退款原路退回 |
| 8 | 员工入职（含建技师档案）→ 排班 → 产生业绩 → 离职（有未完成订单时被拦截） |
| 9 | 技师查看按日/周/月业绩明细 |
| 10 | 管理后台完成排班、订单查询、项目维护 |

**1.3 库存正确性**（本系统的核心）：同一技师、同一床位在同一时段不得被重复占用；下单未支付超时后，被锁定的时段应自动释放。

# 附件四 质保期服务级别（SLA）

## 一、缺陷分级与时限

| 级别 | 定义 | 响应时限 | 修复时限 |
| --- | --- | --- | --- |
| **P0 阻断** | 系统不可用、无法下单或支付、资金计算错误、数据泄露 | `2`小时内 | `24`小时内 |
| **P1 严重** | 核心功能异常但有变通方案，如排班显示错误、报表数据不准 | `1`个工作日内 | `3`个工作日内 |
| **P2 一般** | 非核心功能异常、界面错位、文案错误 | `2`个工作日内 | `10`个工作日内 |
| **P3 建议** | 体验优化建议 | `3`个工作日内 | 双方协商 |

> 响应时限自甲方通过约定渠道提交缺陷之时起算；修复时限自乙方确认缺陷成立之时起算。
> 乙方为个人，无团队轮班，故响应时限较机构标准适度放宽；P0 缺陷仍须尽最大努力即时处理。

> 备用联系人用于乙方失联时的应急联络，由乙方指定并同意甲方在必要时联系。

## 三、逾期责任

乙方未在修复时限内修复 P0 或 P1 缺陷的，每逾期一日按合同总价款的`0.05`%向甲方支付违约金，累计不超过质保金金额。因甲方原因（未提供复现环境、未配合验证）导致的迟延不计入。
