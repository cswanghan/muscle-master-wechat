# PR19 测试用例 — feat: leave approval closed loop and abnormal order resolve

环境：macOS aarch64，`JAVA_HOME=/opt/homebrew/opt/openjdk@21`，Maven 3.9.x。无 Docker。`dev` profile 用 H2 且 Flyway=false；库存/支付/请假/待办走内存仓（work-unit 事务）。不绑定 8080（`RANDOM_PORT`）。

本 PR 补两条设计文档里已定义、但代码里断掉的闭环：

1. **请假审批**：`schedule_exception` 从"只落单"变成"审批后真扣格"，走同一张 `human_task` 队列（`biz_key = leave:{exceptionId}`）。
2. **异常单出度**：`IN_SERVICE → ABNORMAL → COMPLETED / CANCELLED`。此前状态机里有 `ABORT` / `RESOLVE_*` 行但没有任何 API 能触发，`ABNORMAL` 是死状态。

新增迁移 `V5__order_resolve_perm.sql`：`order:resolve` 权限，只发给 SUPER_ADMIN / REGION_MANAGER / STORE_MANAGER —— 前台可以 `ABORT`，但不能自己把异常单结掉。

## TC-19-01 请假审批通过：`FREE → REST`，待办关闭

- **步骤**：`POST /api/v1/a/schedule-exceptions` 提一条 `2026-08-16` 两小时请假 → 队列出现 `LEAVE_APPROVE` 待办 → 店长 `POST /api/v1/f/human-tasks/{id}/approve`。
- **预期**：区间内 8 个格 `FREE → REST`；`slot_occupancy` **不写任何行**（请假不是占用）；待办从 `OPEN` 队列消失。
- **实际结果**：PASS。`ScheduleExceptionApiTest.approveFlipsFreeSlotsToRestAndClosesTask`（restSlots=8，occupancyCount=0）。

## TC-19-02 审批重放不重复扣格

- **步骤**：对同一条请假单再 `approve` 一次。
- **预期**：幂等 —— 不再新增 `REST` 格，不抛 409。

- **预期**：`409 / 40906 LEAVE_CONFLICT`；待办保持 `OPEN`，格不动（先改派/改期，再放假）。

## TC-19-04 驳回不动格；权限与数据域

- **步骤**：`reject` 一条请假单；用只有 `refund:approve` 的 FINANCE 去 `approve`；用别的门店的 token 提请假；提一个非 15 分钟对齐的时间。
- **预期**：驳回 → 格保持 `FREE`、待办 `IGNORED`；FINANCE `40301`（同一个 `/approve` 端点上，`LEAVE_APPROVE` 分支额外要 `schedule:approve`）；跨店 `40302`；未对齐 `40001`。

## TC-19-05 前台中止服务：`IN_SERVICE → ABNORMAL` + 开异常单待办

## TC-19-07 店长出度：`RESOLVE_COMPLETE` / `RESOLVE_CANCEL` / `IGNORE`

- **步骤**：店长 `POST /api/v1/f/human-tasks/{id}/resolve` `{action}`。
- **预期**：
  - `RESOLVE_COMPLETE` → 订单 `COMPLETED`，待办 `DONE`，`resolved_by` = 操作人。
  - `RESOLVE_CANCEL` → 订单 `CANCELLED`（再次释放未消费格）。
  - `IGNORE` → 待办 `IGNORED`，订单**保持** `ABNORMAL`（线下已处理，只清队列）。
- **实际结果**：PASS。`FrontDeskAbortResolveApiTest.managerResolveCompleteFinishesOrderAndClosesTask` / `resolveCancelMovesOrderToCancelled` / `ignoreClosesTaskWithoutTouchingOrder`。

## TC-19-08 出度重放与参数/权限校验

- **预期**：重放返回终态（`replay=true`，`DONE` / `COMPLETED`）而不是 `40904`；前台 `40301`（`FRONTDESK` 没有 `order:resolve`）；跨店 `40302`；坏 action `40001`；不存在 `40401`。以上失败路径都不动订单和待办状态。
- **实际结果**：PASS。`FrontDeskAbortResolveApiTest.resolveReplayKeepsFinalStateInsteadOfConflict` / `frontDeskCanAbortButCannotResolve` / `otherStoreManagerCannotResolve` / `unknownActionIsRejected` / `resolveUnknownTaskIsNotFound`。
