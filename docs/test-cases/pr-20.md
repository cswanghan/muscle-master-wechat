# PR20 测试用例 — feat(observability): 补齐设计 §Observability 指标表

环境：macOS aarch64，`JAVA_HOME=/opt/homebrew/opt/openjdk@21`，Maven 3.9.x。无 Docker。`dev` profile 用 H2 且 Flyway=false；库存/支付/待办走内存仓。不绑定 8080（`RANDOM_PORT`）。

设计文档 §Observability（`docs/p0-technical-design.md` L2112–2123）列了 9 个指标，此前代码里只落了 `inventory.drift` 和 `slot.locked.stale_paid` 两个，其余 7 个没有采样点。本 PR 补齐，并按文档要求把打热表的 gauge 统一节流到 **60s**（"禁止 15s 打热表"）。

新增包 `com.jisuodashi.observability`：

| 类 | 职责 |
|---|---|
| `ScrapedGauge` | 刮取型 gauge 的取值缓存，60s 内复用上次结果 |
| `BusinessMetrics` | `slot.locked.stale` / `store.order.silence` / `workflow.manual.open` / `availability.cache.hit` / `job.release.lag.ms` |
| `PayOutcomeMetrics` | `pay.success.rate`，5 个 1 分钟桶的滚动窗口 |
| `ReleaseScanHeartbeat` | 释放扫描心跳，喂 `job.release.lag.ms` |

计数器留在产生它的模块里：`slot.lock.fail` 在 `SlotOccupyService` 的四个占用入口（`lockNew` / `extendOwn` / `swapTherapist` / `reschedule`）统一拦 `ApiException` 打点，不散在 ~30 个 `throw` 点上。

**口径变更**：原先 `SlotOccupyService` 里直接注册的 `slot.locked.stuck_30m` gauge 被移除，合并为文档命名的 `slot.locked.stale`，并改走 60s 节流。

## TC-20-01 `pay.success.rate` 无流量时不告警

- **步骤**：新建 `PayOutcomeMetrics`，不打任何样本，读 `rate()`。
- **预期**：返回 `1.0` —— 半夜没人下单不该触发"下跌 > 5%"。
- **实际结果**：PASS。`ObservabilityMetricsTest.payRateIsOneWithoutTrafficAndDropsWithFailures`。

## TC-20-02 `pay.success.rate` = success / (success+fail)

- **步骤**：3 次 `success()` + 1 次 `failure()`。
- **预期**：`0.75`；注册到 `MeterRegistry` 后 `pay.success.rate` gauge 读到同一个值。
- **实际结果**：PASS。`ObservabilityMetricsTest.payRateIsOneWithoutTrafficAndDropsWithFailures` / `payRateIsRegisteredAsGauge`（1 成 1 败 → 0.5）。

## TC-20-03 `pay.success.rate` 5 分钟滚动窗口

- **步骤**：打 1 次 `failure()`（此时 `0.0`）→ 时钟推 4 分钟 → 再推 1 分钟。
- **预期**：第 4 分钟仍在窗口内，保持 `0.0`；第 5 分钟样本滚出窗口，回到无流量语义 `1.0`。
- **实际结果**：PASS。`ObservabilityMetricsTest.payRateRollsOffAfterFiveMinutes`。

## TC-20-04 热表 gauge 每 60s 只刮一次

- **步骤**：`ScrapedGauge` 包一个自增计数的 source，模拟 Prometheus 15s 抓取连读 4 次（0s/15s/30s/45s），再在 60.001s 读一次。
- **预期**：前 4 次只触发 **1 次** source 调用（后三次吃缓存）；超过 60s 后才第 2 次真刮。
- **实际结果**：PASS。`ObservabilityMetricsTest.scrapedGaugeHitsSourceAtMostOncePerMinute`。

## TC-20-05 `slot.locked.stale` 刮出卡死锁

- **步骤**：19:00 的固定时钟下锁一单，把 hold 的过期时间改到 18:20（超过 `STUCK_LOCK_MINUTES=30`），`BusinessMetrics.scrapeAll()`。
- **预期**：`slot.locked.stale` 从 0 变成 10（P60 = 4 技师格 + 4 床位格 + buffer，与 `countLockedExpiredBefore` 口径一致），触发文档里的 `> 10` 告警线。
- **实际结果**：PASS。`ObservabilityMetricsTest.businessMetricsScrapesStaleLocksSilentStoresAndOpenTasks`。

## TC-20-06 `store.order.silence` 只数"营业中且 2h 无新单"的门店

- **步骤**：两家演示门店（10:00–22:00，`status=1`）在 19:00 时刻一单未出 → 刮取；旗舰店出一单后再刮。
- **预期**：先 `2`，后 `1`。
- **实际结果**：PASS。`ObservabilityMetricsTest.businessMetricsScrapesStaleLocksSilentStoresAndOpenTasks`。

## TC-20-07 营业时间边界不误报

- **步骤**：`minutesSinceOpen` 直接跑三种边界：打烊后（02:00 vs 10:00–22:00）、刚开门不足 2h（11:00）、跨零点营业（01:00 vs 20:00–02:00）。
- **预期**：打烊返回 `-1`（不计入静默）；刚开门返回 `60`（< 120 分钟，跳过）；跨零点按环形算返回 `300`。
- **实际结果**：PASS。`ObservabilityMetricsTest.closedStoreIsNotCountedAsSilent`。

## TC-20-08 `workflow.manual.open` 只数 `OPEN` 待办

- **步骤**：塞 2 条 `OPEN` + 1 条 `CLOSED` 的 `human_task`，刮取。
- **预期**：`2`。`PaymentStore.countOpenHumanTasks()` 在 JDBC 实现里是 `SELECT COUNT(*) ... WHERE status='OPEN'`，不拉全表。
- **实际结果**：PASS。`ObservabilityMetricsTest.businessMetricsScrapesStaleLocksSilentStoresAndOpenTasks`。

## TC-20-09 `slot.lock.fail` 按 reason 打标签

- **步骤**：同一技师同一格连锁两次，第二次撞 `SLOT_UNAVAILABLE`。
- **预期**：抛 `ApiException(SLOT_UNAVAILABLE)` 的同时，`slot.lock.fail{reason=SLOT_NOT_FREE}` 计数 +1；异常照常上抛，打点不吞错。
- **实际结果**：PASS。`ObservabilityMetricsTest.lockFailureIsCountedByReason`。

## TC-20-10 `availability.cache.hit` 命中率

- **步骤**：对同一 store-day 连读 3 次（1 miss + 2 hit），再读另一天（1 miss）。
- **预期**：`hits / (hits + misses) = 2/4 = 0.5`；无流量时返回 `0.0` 而不是 NaN。
- **实际结果**：PASS。`ObservabilityMetricsTest.cacheHitRatioCountsHitsOverTotal`。

## TC-20-11 `job.release.lag.ms` 扫描没跑起来也会涨

- **步骤**：`ReleaseScanHeartbeat` 在构造（= 启动）时打第一次心跳 → 时钟推 7 分钟读 lag → 跑一次 `SlotScanJob.run()` 读 lag → 再推 1 分钟读 lag。
- **预期**：`420000`（超过文档的 6min 告警线）→ `0` → `60000`。心跳注入用 `@Autowired(required=false)` setter，既有 `new SlotScanJob(occupy)` 构造不受影响。
- **实际结果**：PASS。`ObservabilityMetricsTest.releaseLagGrowsUntilScanRuns`。

## TC-20-12 既有用例不回归

- **步骤**：`JAVA_HOME=/opt/homebrew/opt/openjdk@21 mvn -f server/pom.xml test`。
- **预期**：Surefire 全绿；`dev` 启动无 MySQL/Redis；不绑 8080。`SlotScanJobTest` 里对 `slot.locked.stuck_30m` 的断言随口径统一删除，改为校验刮取源 `countLockedExpiredBefore`。
- **实际结果**：PASS。`Tests run: 380, Failures: 0, Errors: 0, Skipped: 0`（PR19 基线 371 → +9）。
